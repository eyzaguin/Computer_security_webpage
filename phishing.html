CENTRAL RESEARCH QUESTION

How accurately can machine learning models identify spam and phishing emails, and which model performs better at distinguishing suspicious emails from legitimate messages?

01 / SECURITY PROBLEM

Why suspicious email matters

Phishing is a form of social engineering: an attacker impersonates a trusted person or organization to influence someone to take an unsafe action.

THE ATTACK PATTERN

From believable message to security incident

01ImpersonatePose as a trusted sender
→
02Create urgencyPrompt a rushed response
→
03Request actionClick, open, pay, or sign in
→
04Cause harmExpose accounts or data

A successful attack can lead to stolen passwords or financial details, account takeover, malware infection, or exposure of personal and organizational information.

⚠

Spam is not always phishing

Spam describes unwanted or unsolicited messages. Phishing specifically attempts to deceive people into disclosing information or taking an unsafe action. A spam label alone does not prove a message is phishing.

This distinction is essential when interpreting the dataset and describing the research conclusions.

02 / RESEARCH APPROACH

Study the question, not just the score

The project compares two supervised-learning approaches as a way to investigate the research question. The purpose is to understand their behavior and trade-offs, not to assume that a model can reliably determine whether any email is safe.

A

Understand the data

Examine the dataset source, fields, label meanings, data quality, missing values, duplicate records, and class balance before drawing conclusions.

B

Compare approaches

Consider Logistic Regression and Random Forest as two different classification methods for text represented with TF-IDF features.

C

Interpret consequences

Look beyond overall accuracy. Discuss missed suspicious messages, legitimate messages incorrectly flagged, and what these errors could mean in practice.

05 / METHODS & EVALUATION

Two models, explained simply

Σ

LINEAR CLASSIFICATION

Logistic Regression

A supervised classification method that estimates how strongly input features support each class. With text represented by TF-IDF, learned weights can help indicate which terms are associated with each dataset label.

Research consideration: Does a comparatively simple, interpretable text baseline distinguish the dataset's classes effectively?

🌲

TREE ENSEMBLE

Random Forest

An ensemble method that combines decision trees. It can represent non-linear feature interactions, but that flexibility does not guarantee better results on sparse text features.

Research consideration: Does combining trees improve the balance of detection and false alarms on the same evaluation data?

How results should be evaluated

%

Accuracy

Share of all evaluated messages classified correctly. Can be misleading when classes are imbalanced.

P

Precision

Of messages flagged as suspicious, how many actually have the suspicious dataset label?

R

Recall

Of messages with the suspicious dataset label, how many does the model identify?

F1

F1-score

A combined measure of precision and recall, useful when both types of performance matter.

Fair comparison: A rigorous comparison uses the same held-out test data for both models. If labels allow it, stratified splitting can preserve class proportions. Fit TF-IDF only on training data to avoid test-data leakage; use random_state=42 for reproducibility.

06 / SECURITY IMPLICATIONS

When a classifier gets it wrong

FALSE NEGATIVE

A suspicious message is missed

If a harmful message is classified as legitimate, a person may trust it, follow its instructions, and expose credentials or sensitive information.

Potential cost: threat passes through
FALSE POSITIVE

A legitimate message is flagged

If a genuine message is classified as suspicious, important communication may be delayed, hidden, or ignored. Frequent false alarms can also reduce trust in warnings.

Potential cost: valid message disrupted
🏢

How an organization might use this research

A validated classifier could be one signal in a layered email-defense program—for example, helping prioritize messages for review. It should be monitored, combined with other controls, and allow users or analysts to report errors. It should not be the sole authority deciding whether an email is safe.

Labels define the task

A model learns the dataset's labels, not the full real-world meaning of phishing. If labels mean spam, results should be described as spam classification.

Threats change

Attackers change wording and techniques. A model trained on older or narrow examples may perform differently on new messages.

Data may be unrepresentative

Public datasets may not reflect an organization's language, users, email systems, or current threat environment.

Text is only one signal

Sender identity, URLs, attachments, context, and user behavior can also matter; text-only analysis cannot see every signal.

Educational research project. A model prediction is not a guarantee that an email is safe or malicious.
